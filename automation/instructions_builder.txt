## 1. Select ONE item

Read `automation/TODO_LIST.md` and `automation/NEEDS_YOUR_REVIEW.md`, then
`automation/state/dc_automation_state.json`. Pick the first eligible item in
this priority order:

1. Skip anything currently marked blocked in `NEEDS_YOUR_REVIEW.md` (TODO-001's
   filing half, TODO-002 fully, TODO-018 fully — check the file itself in
   case new blocks were added since this text was written).
2. Skip TODO-005 through TODO-011 entirely (content-module authoring —
   paused pending the Notebook-X architecture decision — see
   `NEEDS_YOUR_REVIEW.md`). Do not author new knowledge-base entries for
   these modules under any circumstance this run.
3. Skip TODO-010 unconditionally, even if #2 is later lifted for other
   modules — it needs an owner-approved schema-design split first.
4. Skip any item already marked "Completed" in `TODO_LIST.md`. Also skip any
   item whose most recent `todo_history` entry for that ID has `"status"`
   of `"done"`, `"in-progress"`, or `"needs-review"` — checked across ALL
   days, not just today; a stale unmerged "done" from a prior day is
   exactly as blocking as one from today.
   - **"Most recent" means array/append position, not the `"date"` field.**
     `todo_history` entries are only ever appended, never reordered or
     edited in place, so the LAST entry for a given ID in the array is
     always the authoritative current status — read the array in order and
     take the last match for that ID. Do NOT try to determine recency by
     comparing `"date"` string values: `date` is day-granularity only (no
     time-of-day), and a Builder entry followed by a same-day Auditor entry
     for the same ID — which happens routinely, e.g. `done` then
     `needs-review` both dated the same day — would be indistinguishable
     by date alone. Array order is the only reliable signal.
   - `"needs-review"` means an Auditor run already declined the item for a
     specific reason recorded in `NEEDS_YOUR_REVIEW.md` — this is a hard
     skip, not a "try again and hope it's cleaner this time." Do not
     re-attempt a `needs-review` item on your own judgment, even if you
     believe you'd avoid the same mistake (e.g. a scope-bundling issue).
     It stays skipped until a human explicitly re-queues it — look for an
     explicit note in `NEEDS_YOUR_REVIEW.md` or a new `todo_history` entry
     with `"status": "cleared-for-retry"` that appears AFTER the
     `needs-review` entry in the array for that ID; if neither exists, it
     is still blocked.
   - If the most recent entry for an ID is `"failed"`, it is NOT
     automatically skipped — treat it as eligible again (a fresh attempt
     may succeed), but read the failure note first so you don't repeat the
     same mistake.
5. From what remains, prefer this order: TODO-003, TODO-004, TODO-014,
   TODO-016, TODO-017, then TODO-001 (UI/parser half only — do NOT build
   the GitHub-write half, that stays blocked), then TODO-012, TODO-013,

6. If nothing is eligible: log "no eligible item this run" to
   `automation/DATA_CENTER_RUN_LOG.md` (create the dated section, write one

   `last_run` timestamp only, and stop. Do not invent work. Do not touch
   any other file.

Note on TODO-012/013/015: these produce a written recommendation document,

## 5. Update the state file

Update `automation/state/dc_automation_state.json`: set `last_run` to the
current time as **true UTC**, ISO-8601, `Z`-suffixed (e.g. `2026-07-20T12:11:57Z`)
— convert from local wall-clock time if your environment reports local
time; do not relabel a local timestamp with a `Z` suffix without
converting it, that produces a value that is off by your UTC offset and
misleads anyone reading the file by hand. `last_run` is informational only
(not read by any selection logic), but it must still be accurate. Then
append one entry to `todo_history`:

```jsonc
{
  "id": "TODO-XXX",
  "status": "done" | "failed" | "needs-review",
  "branch": "dc-auto-<STAMP>",
  "run": "builder",
  "date": "YYYY-MM-DD",
  "note": "short human-readable summary"
}
```

Use `"done"` if you completed the item and validators passed (this does NOT
mean merged — that's Run 2's decision). Use `"failed"` per step 3. Use
`"needs-review"` if the item is scoping-only (TODO-012/013/015) or otherwise
inherently non-mergeable-by-checklist.

**MANDATORY when you write `"needs-review"`: you must ALSO append an entry to
`automation/NEEDS_YOUR_REVIEW.md` in the same run, before you finish.**

This is not optional bookkeeping — without it your work is invisible. A
`needs-review` item is never merged by the Auditor (correct — a recommendation
doc can't pass the Push-Authorization Checklist) *and* is a hard skip for every
future Builder run (step 1.4). So the branch is terminal: nothing will ever
pick it up again automatically. If you don't write it into
`NEEDS_YOUR_REVIEW.md`, then from `master`'s point of view nothing happened at
all — `TODO_LIST.md` still lists the item as open, the recommendation doc
exists only on an unmerged branch, and the owner has no way to discover it
short of manually running `git branch -r`. This has already happened twice
(TODO-012 on 2026-07-25 and TODO-013 on 2026-07-26 both produced complete
recommendation docs that were never surfaced anywhere on `master`).

Use this format, under a new dated heading:

```markdown
## TODO-XXX — recommendation ready for your review (branch not merged)

*(added YYYY-MM-DD by the Builder run)*

**Branch:** `dc-auto-<STAMP>` (pushed, deliberately not merged)
**Deliverable:** `automation/recommendations/TODO-XXX-<slug>.md` — exists only
on that branch until you decide.
**Recommendation in one line:** <the actual conclusion, not "see the doc">
**What we need from you:** read the doc, then either (a) merge the branch
yourself, (b) tell the automation to drop it, or (c) re-queue the item by
appending a `"status": "cleared-for-retry"` entry for this ID.

To read it without merging:
```
git show <branch>:automation/recommendations/TODO-XXX-<slug>.md
```
```

Write the one-line recommendation properly — the owner should be able to
decide whether to even open the branch from that line alone.
